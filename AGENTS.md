# AGENTS.md

## What this repo is

A **study/planning repo** (pt-BR docs), not an application. The goal is designing a ReAct agent "harness" for local LLMs (Ollama + OpenAI-compatible SDK, Deno runtime) to later feed improvements into the external project [OllamaTask](https://github.com/Erik-Castro/OllamaTask). The actionable deliverables are the docs, not the code.

## Implementation notes (harness v1, in `src/`)

- `ReAct.run(prompt)` is an **async generator** `AsyncGenerator<AgentEvent, TExecutionResult, void>` (suggests.md §3A) with the spec §5 callbacks (`onToolCalling`, `onToolResponse`, `onReasoning`, `onContent`) as a thin façade. Scope: core loop + self-healing tool calling (§C) + context management (§B, deterministic + opt-in LLM summarization).
- Provider is injectable (`ReActOptions.responses`) for offline tests; `cancel()` aborts via `AbortController`; `reset()` clears history; `maxRounds` + context management (`maxContextItems`/`maxContextChars`) prevent unbounded loops.
- **Parallel tool calls (§C)**: request leva `parallel_tool_calls` (default `true`) — tools **non-sensitive** in a round run via `Promise.all` (batched), results cached by `call_id` and applied in the **sequential pass** (deterministic event/history order). Order NEVER comes from `flock` — it comes from the sequential await pass (probe: `Deno.open({ lock:true })` does NOT serialize two opens within the same process on this runtime; peak writers = 3, second open = 0ms). `flock` is best-effort/advisory between processes only. Sensitive/HITL tools stay sequential (§D).
- **Context management (§B)**: deterministic `prune()` (splice oldest, bounded by `maxContextItems`/`maxContextChars`) is the default and the safety net. Opt-in `ReActOptions.summarizer` (a `Summarizer`, factory: `createLLMSummarizer(responses)`) runs **before** each round when items/chars/tokens overflow: the oldest prefix (everything before the last `summarizeKeepRecent` items, default 6 ≈ 2 interactions) is condensed into ONE `role:"system"` item ("Resumo do contexto anterior:...") reusing the same model/provider via a tool-less single call sharing the run's `AbortSignal`. Empty/error summary falls back to `prune()` and never throws; `cancel()` during summarization aborts cleanly. `TExecutionResult` gains additive `summaries`; getter `agent.summaries`.
- **Token-based trigger (§B, spec/suggests 80% da janela)**: implemented as a two-layer measurement — when `ReActOptions.maxContextTokens` (>0) is set, `manageContext()` triggers when `contextTokens() > ratio × maxContextTokens` (default ratio 0.8, clamped (0.01,1]). `contextTokens()` prefers the **real `usage.input_tokens` from the previous round**; when the provider reports none it falls back to `estimateTokens()` (**~4 chars/token heuristic**, `src/tokens.ts`, injectable via `ReActOptions.tokenEstimator`). Deviation: the heuristic is an approximation (no offline tokenizer) and the system prompt/tools are not included in the estimate. Disabled by default (behavior unchanged without `maxContextTokens`).
- Self-healing: `ToolRegistry.executeSafe` never throws — returns `{ok:false,error}` for unknown tools/malformed JSON/non-object args/schema violations; the loop injects a system message with the error and continues.
- **HITL (suggests.md §D) is active**: a `Tool` with `sensitive: true` makes `run()` yield `tool_interrupt` and pause (`state === "paused"`) until `resume(true|false)`. `true` executes normally; `false` does NOT execute, injects a `function_call_output` with the denial (keeps history consistent, same shape as §C) and yields `tool_denied` (`reason: "user"`). `cancel()` while paused resolves the pending approval as denied → generator ends with `aborted`, no deadlock. `resume()` with no pending approval throws.
- **HITL advanced**: `resume(true, params)` overrides the model's args — the override is revalidated by `executeSafe` (invalid override falls into the §C self-healing path) and a `role:"system"` note tells the model the args were adjusted. `resume(false, params)` ignores params (pure deny). Optional `ReActOptions.approvalTimeoutMs` (default 0 = unlimited): when it expires without a decision, the harness auto-denies (`tool_denied` with `reason: "timeout"`), so a vanished consumer can't deadlock the generator. Priority: `cancel()` > timeout > `resume()`.
- **Zod validation**: `Tool.parameters?: z.ZodTypeAny` — `executeSafe` validates with `schema.safeParse` (issues joined as `$.path: message; ...`), `toOpenAITool` converts via `z.toJSONSchema` (strips the `$schema` keyword so local providers like Ollama don't choke), and `loadRuntimeConfig` validates env with `z.object` (coerce int for `OPENAI_MAX_RETRIES`, url + http/https refine, trims, empty → default). `types.ts` imports zod **type-only** (`import type { z } from "zod"`); runtime value imports live in `tools.ts`/`config.ts`/`config_test.ts`.
- **Deviations from the docs** (deliberate): real delta event names replace spec §4's hypothetical ones; `Tool.execute` receives a *parsed* params object (not JSON string); `system_prompt` is sent via the `instructions` request param (keeps it out of message history); `TExecutionResult` is additive-extended with `rounds`, `toolCalls` and `summaries`; errors become `error` events (never thrown through the generator).
- **Type-import rule**: use `import type { Responses } from "openai/resources/responses"` and qualify with `Responses.` directly. A local type alias (`type R = Responses`) CANNOT be used for qualified names (`R.ResponseStreamEvent` fails). Same applies to `OpenAI.Responses` via alias.
